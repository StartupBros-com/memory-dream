The short answer The 2026-07-16 ideation is confirmed fully superseded — structurally, not just by progress: every commit in this repo postdates it (the plugin was extracted from the private harness starting 2026-08-08), and that doc addressed the predecessor dotfiles memory system. The repo today is in unusually good shape (v0.2.1, 191 tests, zero TODOs, stdlib-only), and 2026 external evidence validates the current proposal-only, reversible, operator-gated posture — the strongest research finding argues against more autonomy, which is the most tempting over-engineering direction. What remains is a short list of small closes: one real bug, several self-admitted loose ends, two credibility gaps (a verification check that exists only as a doc claim, and a positioning question with no answer), and review-burden trims that reduce ceremony rather than add it.

Grounding Context

Codebase Context

State: v0.2.1 at ee628fd; 191 tests passing; zero TODO/FIXME; zero runtime deps (CI-enforced). Three layers: deterministic triage (audit.py, no model calls) → deterministic assemble/apply plumbing → model-driven dream pass with a zero-tool drafter and a five-stage verification stack, behind a 7-gate apply. Every threshold lives in config.py, documented in docs/TUNING.md and docs/ARCHITECTURE.md. README.md is the product doc.

Self-admitted gaps (the repo's own words): thresholds "calibrated once, on one corpus" (~500 English notes, 2026-07); index caps "measured against Claude Code v2.1.211" and non-API; PATCH_SET_RETENTION_DAYS "does nothing on its own"; the active-session warning "becomes a false alarm the operator learns to ignore"; differentiation is one unelaborated sentence.

Recent activity since the old doc: extraction to marketplace-shippable state, Windows correctness, skill-tuner suite integration, release-train wiring, and one substantive security fix (compaction summaries forging operator consent, v0.2.1) — infrastructure hardening, no core-pipeline scope growth. No docs/solutions/ learnings corpus exists (learnings search skipped).

External evidence (web research, value: high)

  • "Useful Memories Become Faulty When Continuously Updated by LLMs" (2026) — forced repeated LLM consolidation degrades agent performance (100%→54% in one case); each abstraction pass is a lossy rewrite that compounds. Empirical support for proposal-only, against autonomy.
  • Rate-distortion survey "What to Keep, What to Forget" — reversibility is the property separating schemes that degrade gracefully from ones that compound error; validates snapshot + archive-don't-delete.
  • Letta sleep-time best practices — expiry-policy table (decisions never expire; "reference count matters more than age"); explicit "don't over-consolidate — you lose granularity."
  • Claude Code's native Auto Dream (~Feb 2026): background consolidation, same "dream" framing, no operator diff/approval, no verification or measurement layer. Closest built-in competitor. Single-web-sourced (docs, guide) — verify before citing in the README.
  • Memory poisoning is an active 2026 research area (GhostWriter/AM-Sentry, MPBench, Trojan Hippo, Zombie Agent, eTAMP): the zero-tool drafter + schema validation + sensitive-skip + operator review is architecturally the strongest mitigation pattern the research surfaced — a differentiator to state, not a gap to fill.
  • Two unrelated production postmortems converged on manual, periodic (every 2–4 weeks) consolidation over continuous automation — triangulated support for the operator-invoked cadence.

1One honest drift doctor

environment-drift Confidence 85% Complexity Medium
Description
Make doctor the single honest answer to "did anything drift under me." Five parts, all advisory: (a) consolidate the "measured against Claude Code v2.1.211" pin — currently six hand-synced copies across config.py, audit.py, cli.py, TUNING.md, README.md, EXTRACTION-DESIGN.md — into one compatibility record all sites interpolate; (b) fix the found bug: the index-cap doctor check passes a literal True (cli.py:129-136) and structurally cannot fail — compare the installed CLI version against the measured one instead; (c) a transcript-schema canary that asserts the consent-gate flags (isCompactSummary/isVisibleInTranscriptOnly) against the operator's own transcripts — today's schema_probe (transcript.py:77-113) checks only parseability, not gating, which is exactly the gap the v0.2.1 incident exploited; this doubles as a live, re-runnable proof of the CHANGELOG's 348/348 claim; (d) list any config value that differs from its shipped default, with its source (env/JSON) — no override-reporting exists today; (e) surface the already-computed flagged:N readiness signal, and offer one aggregate --strict verdict for post-upgrade scripts.
Basis
direct: cli.py:129-136 hardcoded True (verified); six v2.1.211 copies (verified by grep, 6 files / 7 lines); transcript.py:77-113 parse-only probe (verified); the v0.2.1 consent-forgery incident (CHANGELOG, PR #11) as the proven failure class.
Rationale
This is the one drift class that has already produced a real security bug, and the mitigation today is "the operator remembers they upgraded." All five ideation frames independently converged on some form of this — the strongest convergence signal in the run. Every piece converts a recall-dependent habit into a check the tool runs, using the advisory pattern doctor already ships.
Downsides
Doctor grows surface (keep everything advisory, one aggregate line, or it becomes its own noise); the canary needs a readable current transcript at run time; shelling out to claude --version adds one environment dependency.

2Deterministic quote-existence gate for panel findings

positioning-trust Confidence 85% Complexity Low
Description
Require every verification-panel finding to carry a machine-readable quoted span plus file reference (the current finding schema in templates/fidelity-prompt.md has only claim/problem/fix), and substring-check that span in code before the finding ever reaches model adjudication. Findings whose quote fails the check get flagged as unverifiable rather than silently trusted or dropped. Also fix agents/scribe.md:24-25, which currently claims "quote-existence checks on findings" happen — no such code exists anywhere; the only check today is a model-diligence instruction in commands/dream.md:350-354.
Basis
direct: docs/PROVENANCE.md:115-126 — panels "produce confident false positives… a quoted passage that did not actually appear in any file"; the scribe.md doc/reality mismatch (verifier-found); precedent: recall_eval.py:183 already runs exactly this substring check for another stage ("answer_snippet not found in source note (fabricated?)").
Rationale
This closes a dated, measured failure mode (2026-07-20) with str.find()-level code, and it tightens an existing stage rather than adding one. The whole product's trust claim is "it measures" — yet the layer that checks the drafter's work currently asks the operator to re-verify its claims by hand, and one doc oversells a guarantee no code backs. Both halves are pure credibility repair.
Downsides
Panels must be prompted to emit exact spans, which touches the finding schema, the panel templates, and the verification-coverage gate; genuinely paraphrase-shaped findings need a fallback lane (flag, don't discard) so the gate doesn't suppress real observations that lack a quotable span.

3The pipeline remembers its own decisions

operator-experience Confidence 80% Complexity Low
Description
Two symmetric halves. Suppress-on-reject: selection.json records only approved IDs; nothing remembers what the operator turned down, so the next pass re-drafts and re-verifies the same cluster. Extend the existing SUPPRESS_APPLIED_DAYS mechanism (config.py:32) to rejected cluster signatures. Repeat-deferral visibility: assemble.py already persists per-item deferral detail ({project, path/cluster_id, reason} at assemble.py:108/:131) but the operator is shown only counts (dream.md:99-100) — surface which clusters keep losing the per-pass cap, pass after pass.
Basis
direct: all four code/doc claims verified by the fresh-context pass: approved-only selection.json, applied-only suppression, persisted-but-unsurfaced deferral records, counts-only reporting.
Rationale
"Rot accumulates unseen" is the exact failure this tool exists to fix in raw memory — and it recurs one layer up, inside the pipeline's own queue: a cluster can starve silently every pass, and a rejected proposal costs drafting and verification tokens again every pass. Both fixes reuse an existing mechanism or existing data; neither adds a pipeline stage.
Downsides
Rejected clusters need a stable signature that survives note renames/merges; suppression must decay (a rejection today isn't a rejection forever) — mirroring the applied-side day-window handles both.

4Close the retention loose ends

loose-ends Confidence 85% Complexity Low
Description
Three separate code paths each create a copy of full memory-note content and assign deletion to the operator with no enforcing code: patch sets (PATCH_SET_RETENTION_DAYS — "does nothing on its own," TUNING.md:83), mirror-prune targets (ARCHITECTURE.md:187-198), and the WSL preview copy ("tell the operator to delete it after review," dream.md:503-506). Pick a resolution: (a) cheapest — a doctor advisory counting overdue patch sets, using the exact crash-leftover glob pattern doctor already ships; (b) fuller — one cleanup command sweeping expired patch sets (including preview copies) and reporting outstanding mirror-prune targets; or (c) delete the knob and the placeholder MIRROR_PUSH_HINT rather than shipping config whose own docs say it's inert.
Basis
direct: config.py:59 ("advisory; pruning is operator-owned"), TUNING.md:83, dream.md:503-506, and the existing *.dream-tmp advisory pattern in cli.py — all verified.
Rationale
Unbounded accumulation of sensitive-content copies sits badly next to the tool's own privacy posture, and all five frames converged on this gap independently. The shared shape (tool creates copy, doc assigns cleanup, no code) means one decision closes three admitted gaps — the discussion is which resolution, not whether.
Downsides
An actual prune is destructive code in a tool whose identity is "never deletes" — the advisory-count option deliberately sidesteps that; deleting the knob forecloses a documented extension point some operator may already script against.

6Attention where the model touched content

operator-experience Confidence 75% Complexity Medium
Description
Make review ceremony proportional to model involvement, in three trims: (a) the active-session warning — which TUNING.md:82 admits "becomes a false alarm the operator learns to ignore" — refires only when sibling-session state has actually changed (alarm-rationalization practice), or is demoted with a concrete "session X, active Y minutes ago" message; (b) the archive tier — fully deterministic, body-untouched, reversible (dream.md:641-655) — gets a coarser batch approval, since SECURITY.md:85-86's per-item-review rationale (catching what "an automated forgery cannot anticipate") doesn't apply to a script-provable line move; consent stays mandatory, just at tier grain; (c) one aggregate line atop preview.html ("N proposals, all fidelity-clean, 0 flagged") from signals assemble.py:820-823 already computes, so a clean pass approves in seconds and a flagged pass still routes to per-item diffs.
Basis
direct: all three anchors verified (TUNING.md:82, dream.md:641-655 + SECURITY.md:85-86, assemble.py:820-823). external: ISA-18.2-style alarm rationalization — suppress non-actionable repeats, alert on state change.
Rationale
Per-item diff review is the product's core control, and its credibility is currently being spent on false alarms and on ceremony for operations a script can prove. Habituation is the documented failure mode — protecting operator attention is protecting the gate. This is the survivor set's one genuinely ceremony-reducing idea, which is exactly what the focus asked for.
Downsides
Batch approval is a consent-semantics change and needs a careful SECURITY.md definition so proposal-only stays intact; the rollup line must never become a reason to skip diffs on a flagged pass (route flagged passes unchanged).

7Standing recalibration, sentinel-sized

threshold-calibration Confidence 60% Complexity Medium
Description
The paired-flip eval machinery (suite hashing, noise bands, discriminability check) exists and has been used twice as ad hoc shadow experiments (2026-07-18/31). Package it as a recalibrate command; run it against a small fixed sentinel corpus (~20–30 notes, deliberately including the non-English and edge-case shapes the docs flag as untested) as a cheap drift canary; add a doctor advisory comparing current corpus size to the ~500-note calibration baseline. Full recalibration happens only when the sentinel drifts — the epidemiological sentinel-site pattern, not a standing campaign.
Basis
direct: recall_eval.py machinery and both dated recalibration events verified; "defaults, not truths" (TUNING.md:16-18). reasoned: the gap is not missing infrastructure but a standing way to notice drift between rare full campaigns.
Rationale
"It measures, doesn't assume" is the product's identity, and every tunable is self-admittedly a one-time measurement. This makes re-measurement a command instead of tribal knowledge — the packaging is the whole idea; no new eval science.
Downsides
The most process-shaped survivor: the sentinel corpus needs curation, and an unrepresentative sentinel is eval theater. If it can't stay ~30 notes and one command, don't build it — that judgment is why confidence is 60%.
